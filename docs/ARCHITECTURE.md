# Architecture

## Big picture

One HTML page, fifteen plain scripts, no framework, no build.  Every script adds one module to a single global object, `window.GW`, and the load order in `index.html` matters:

| Order | File | Module | Job |
| --- | --- | --- | --- |
| 1 | `js/config.js` | `GW.CONFIG`, `GW.VERSION` | All tuning data.  Items, gnomes, upgrades, odds, hats, placements, branding. |
| 1a | `js/destinations.js` | `GW.DESTINATIONS` | Generated by `node tools/destinations.js`; never edit by hand.  The Packing Line's destinations from the map's locations file (`docs/lore/map/gnomadica-locations-v0.29.json`): the ten regions in unlock order with their stamp color and symbol, and every place whose Factory Imports names a game item, with its `buys` list of item ids (the whole Bathroom group included).  `js/shipping.js` reads it for the work orders (1c-2). |
| 1b | `js/theme.js` | `GW.theme` | Day / Night.  `img(path)` returns a picture's `_night` twin when Night is on.  An inline script in `index.html` sets the `night` class before anything draws. |
| 2 | `js/util.js` | `GW.util` | `fmt()` big-number formatting (K, M, B ... then exponent), random helpers, DOM shortcuts |
| 3 | `js/sfx.js` | `GW.sfx` | Sound effects synthesized with Web Audio, plus a few recorded samples (`assets/sfx/`) with code-made fallbacks |
| 4 | `js/state.js` | `GW.state` | Save data: `fresh()`, `load()`, `migrate()`, `save()`, `wipe()` |
| 5 | `js/economy.js` | `GW.econ` | All game math.  It reads and changes only the state object. |
| 6 | `js/gears.js` | `GW.gears` | The Machine view: SVG wall image, Mara's gear images, the hatch flap |
| 7 | `js/ui.js` | `GW.ui` | Shop, shelf, stats, crew strip, Shop Floor, floating text, toasts, squish animations |
| 7b | `js/wild.js` | `GW.wild` | Wild Magic event |
| 7c | `js/clones.js` | `GW.clones` | Clone Attack event |
| 7d | `js/mega.js` | `GW.mega` | The Megagnome: shop row, food, poses, helping in events |
| 7e | `js/hunt.js` | `GW.hunt` | The crossbow hunt mini-game |
| 7f | `js/shipping.js` | `GW.ship` | The shipping room (Packing Line): room art, door chain, truck and driver, work orders on the order board, the item menu, packing and stamping, the hand-off, the report card, and the GRIP line on the STONKS screen.  Hidden unless enabled or `?ship=1` |
| 8 | `js/main.js` | (runs once) | Loads the save, wires input, runs the game loop, shinies, pause, sound settings, autosave |

The rule that keeps this sane: **economy reports, UI draws.**  `GW.econ` changes numbers and returns an `events` object (items made, items to animate, new discoveries).  `main.js` hands those events to `GW.ui` and `GW.sfx`.

## The game loop (`main.js`)

`requestAnimationFrame` drives everything.  Each frame:

1. Work out `dt` (seconds since last frame).  If paused, or if the factory is resting (below), push timers forward and skip the economy and every event tick.  If `dt` is over 5 seconds (the tab was asleep), run the offline catch-up instead of a normal tick so thousands of items do not try to animate.
2. `econ.tick(s, dt, events)` adds gnome clicks for the elapsed time.  Each gnome type is credited in Stats, but the gear turns and items roll once per tick for all of them together (rolling per type was the late-game lag).
3. The big gear's display angle chases the logical angle, capped at 540 degrees a second so it never blurs.
4. Queued item pops drain at up to 3 a second; any extra become a "+N items" note.
5. Shinies spawn, glow gold when "hot," and expire.  Events tick: `GW.wild.tick`, `GW.clones.tick` (see [EVENTS.md](EVENTS.md)).
6. Shop Floor animations fire (`ui.animateFloor`).
7. The header updates every frame; shop, crew, stats, and shelf update every 0.25 seconds.
8. Autosave every 10 seconds, plus on tab hide and page close.

**The factory rests in the Shipping view (1c-3, Nathan 2026-11-23).**  `resting()` in `main.js` (also `GW.game.resting()`) is true while `s.view` is `'shipping'`, and it is the one rule every producer, event, and pop-up checks.  While resting, `frame()` runs the pause branch (timers pushed forward with each event's `shift(ms)` and the shiny's `expires` and `nextPopupAt`), skips `econ.tick` and every event tick, drops any queued item pops, and skips shinies; Time played still counts.  `GW.wild.start`, `GW.clones.trigger`, and `GW.hunt.open` refuse while resting.  The `resting` class on `body` hides anything frozen mid-event (`#rareSlot`, `#edgeFlash`, `.clone-alert`, `.strike-sign`, `.hunt`) with `visibility: hidden` and paused animations, so it carries on untouched when the player returns, and entering the room clears a toast already showing.  **Resting time is time away:** `restCheck()` (run on every view change and pause toggle) starts a wall-clock count (`restSince`) when the room opens unpaused, and on leaving the room, or pausing in it, pays the seconds once through `E.offline()` (its usual 8 hour cap, efficiency, and 5 second minimum) and marks the shelf dirty.  `GW.state.save()` writes `savedAt` as now minus the unpaid seconds (`GW.game.restOwed()`), so a close or reload in the room pays them once through the welcome-back catch-up, and a save after leaving owes nothing.  A new producer or event ticks from the normal branch of `frame()` and checks `GW.game.resting()` in anything that can start it outside that branch.

## Input and anti-cheese

- Taps come from `pointerdown` on the machine box (Machine and Shop Floor views; the shipping room does not crank the machine).  Touch swipes between views work on the Machine and the Shop Floor, not in the Shipping view.  Events with `isTrusted === false` (scripted) are ignored.
- A token bucket caps taps at 20 a second.
- Space or Enter on the focused machine also taps, and held-key repeats are ignored.
- Shinies are claimed only by a trusted tap on the shiny itself.  No gnome or upgrade can claim one.
- A shiny is "hot" (gold) when the gear was tapped in the last 30 seconds.  Only hot shinies can be Legendary.

## Save data (`state.js`)

Stored in `localStorage` under `gnomeworks.save`, so a save belongs to one browser on one exact web address.  Moving the game to a new address starts everyone over.

```
schema, season, createdAt, savedAt
paused, view ('machine' | 'floor' | 'shipping'; 'shipping' falls back to 'machine' on load while that view is hidden), audio { fx, chatter, muted }
cogs, cogsSeen (lifetime, drives unlocks), bigAngle (0-360), itemsMade
producers { id: count }, leveled { id: level }, oneTime { id: true }
revealed { "kind:id": true }   shop rows stay visible once unlocked
items { id: count }, seen { id: true }   shelf and NEW badges
clicks { tap, tiny, tinier, warrior, stick, cloner, matryoshka, wizard }   Stats tab
bonusCogs { items, sprockets }
stonks (the Packing Line's score, never spent, never below 0), stonksHistory [ Stonks after each of the last 10 shifts, oldest first ]
stats { taps, playSeconds, popupsSeen, popupsClaimed, pity, legPity, bestCps, sprockets,
        wildEvents, wildCleared, clonesSplooshed, clonesEscaped }
```

- Kept outside the save, per browser: `gnomeworks.theme` (auto, day, night) and `gnomeworks.hints` (on, off).
- `migrate()` fills any field a newer version added, so old saves never crash.
- If `season` in the save differs from `CONFIG.season`, the save is discarded and a "new season" toast shows.
- A corrupt or blocked save starts fresh with a toast.

## Economy math (`economy.js`)

| Quantity | Formula |
| --- | --- |
| Gnome cost | `baseCost * growth ^ owned` (growth 1.15) |
| Leveled upgrade cost | `baseCost * growth ^ level` |
| Clicks per item (one big-gear turn) | `max(3, 20 * 0.85 ^ ratioLevel)` |
| Global multiplier | `(1 + 0.25 * fasterGearsLevel) * (1 + 0.10 * autoPokerLevel)` |
| Tiny gnome rate | `0.5 * 2^(inventions owned of: two_hands, inv_mitts, inv_elbows, inv_steam)` each |
| Other gnome rates | `count * rate * upgradeMult * global * wizardAura` (Necromancer 4, Cloner 40, Matryoshka 260, Wizard 1,400).  `upgradeMult` comes from one-time upgrades with `mult: { producer, x }` (the Wizard's x2s). |
| Wizard aura | With "Not the Cog, But You": every other gnome type gets `+1%` per Wizard, capped at `+50%` (`wizardAura`).  The Wizard doesn't boost himself. |
| Warrior | `count * 2 swipes/sec * weapon value * global` (dagger 3 up to gnome-on-a-stick 8) |
| Gnome on a Stick bonus | `+1 click per swipe`, tracked separately as `stick` |
| Tap value | `(1 + brassKnucklesLevel) * fasterGears`, plus 5% of gnome clicks/sec with Rally Cry |
| Cogs | 1 per click, plus an item bonus of `tier.bonus * clicksPerItem` per item |
| Machine drops | Weighted by tier: Common 70, Uncommon 22, Rare 12.  Super Rare and Legendary have weight 0 (shinies only). |
| Big batches | Over 200 items at once are split by expected value instead of rolled one by one |
| Offline catch-up | `min(seconds away, 8 hours) * efficiency`, skipped entirely while paused |

**Shinies:** every 45 to 120 seconds, staying 20 seconds.  A claim rolls Legendary at 9% (hot only), Super Rare at 45%, otherwise a Lucky Sprocket worth 60 seconds of production (minimum 50 taps).  Pity: a Super Rare or better by the 6th claim, a Legendary on a hot shiny by the 25th.  Picks favor items the player does not own yet (weight 3 versus 1).

## The views

**The Machine (`gears.js`).**  An SVG with a 1000 x 1000 viewBox.  The wall is Mara's painted machine (`assets/bg/machine_wall.webp`) with gear mounts painted in.  Four of Mara's gear images sit on those mounts: drive (8 teeth) to a compound gear (12 teeth with a 7 tooth pinion on its face) to the big gear (15 teeth).  Gear angles come from a meshing formula, so each gear's speed follows real tooth ratios, and each image has a measured `phase` so its teeth line up.  The hatch flap is the only drawn part; it swings open on each drop.

**The Shop Floor (`ui.js`, `#floor` inside the machine box).**  A CSS container with Mara's three-level workshop as the background: `floor.webp` (16:9) on wide screens and `floor_tall.webp` on screens 720px wide or less.  `CONFIG.floor.layouts` holds each layout's 12 station slots (x %, feet line %), plate placement, belt rectangle, and a sprite scale.  Sizes use container query units (`cqh`, `cqw`) so everything scales with the box.  Each owned gnome type gets its station; empty ones show HELP WANTED.  Items ride the conveyor instead of popping from the hatch.

**The shipping room (`shipping.js`, `#ship` inside the machine box).**  The Packing Line's room, built so far up to layer 1k (the room, the door, the truck and driver, the work orders, packing, the hand-off, the leave warning, the supplies menu and the room's tips, the inside supplies, the outside stickers, and the 1k polish).  Hidden from players: it exists only while `CONFIG.shipping.enabled` is true or the address has `?ship=1`; otherwise its button stays hidden, swipes skip it, and a saved `view: 'shipping'` loads as the Machine.  `room_wide` above 720px and `room_tall` at 720px and under, with Night twins through `GW.theme.img()`.  The closed room and its open twin are stacked `<img>`s, so they swap with no jump.  **The rolling door (1k):** `.ship-door` is a third copy of the closed room, just above the twins and under everything else, clipped to the layout's `doorway` grown by `trip.doorPad` % on every side (the twins match outside that, measured on both themes).  `rollDoor(up)` shows the open twin, then animates the door's `clip-path` with its bottom edge climbing to its top edge (`doorClip()`), over `trip.doorUpMs` or `doorDownMs`, and plays `GW.sfx.rattle(trip.rattle, secs)`; reduced motion fades its opacity over `trip.doorCalmMs` instead.  `settle()` hides it.  The pull chain (`.ship-chain`) sits where `CONFIG.shipping.layouts.<wide|tall>.chain` puts it, with a wider invisible tap area (`hitW`).  A trusted tap bounces the chain and starts a trip.  **Trip states** (`GW.ship.tripState()`): `closed`, `arriving` (the door rolls up, the truck slides in from the right and settles, then the driver walks in from the doorway), `here`, and `leaving` (the driver walks out, the truck slides away, then the door rolls down).  Chain taps during `arriving` or `leaving` are ignored.  The truck sits in `.ship-bay`, a full-room layer with a `clip-path` from `layouts.<layout>.truckClip` if the layout has one, else `.doorway`.  Both layouts have a `truckClip`, so the truck backs into the room: it draws over the left jamb, the wall, and the floor, and only the header and the right jamb stay in front.  `.ship-roller` repeats the room art (both twins) cut to `layouts.<layout>.roller`, above the chain, so the chain's top end hides behind the roller's gear cap through the pull.  Motion uses the Web Animations API; every position, size, and timing is in `CONFIG.shipping` (`layouts.<layout>.truck` and `.driver`, and `trip`).  Reduced motion keeps the slides and walk but drops the settle bounce and the step bob.  Changing layout mid-trip skips to where the trip was heading.  The truck's size and stopping place are measured from Nathan's mocks (desktop mock 1, the phone mock), with its wheels on the floor.  The driver waits in his grumpy pose at `layouts.<layout>.driver.at`, full size, following the depth rule (his feet lower on screen than the floor contact of anything he stands in front of): in the wide room centered on the doorway just in front of the sill, in the tall room in front of the bench's right end (where Nathan's phone mock has him).  He is drawn in front of the truck, the doorway frame, and the bench.  The phone driver matches the wide room's driver-to-bench ratio; the phone truck is sized from Nathan's phone mock.  The truck and driver ignore taps.  **Work orders (1c-2).**  When the driver finishes walking in (the trip turns `here`), `makeOrders()` makes up to `CONFIG.shipping.orders.count` orders: each picks a random place in `orders.region` from `GW.DESTINATIONS`, then a random item from that place's `buys` that the shelf holds more than `orders.keep` of and no other order on the board asks for; a place with nothing to spare is passed over.  **Counts (1h):** `pickCount()` gives the order its `qty`, a random number from `orders.counts[item.pack || '']` no larger than the shelf count less `orders.keep`, or that spare count itself when none fit.  Item tags are `pack: 'heavy' | 'breakable' | 'soft'` on the junk items in `CONFIG.items` (none on the rest).  `countName()` writes "500 × Toilet Paper" (`orders.countSign`) for the slip's ITEM line and the card's item line.  On the slip the name and picture are one no-wrap `.slip-tail`, so a narrow line puts the count above them, and `fitSlips()` (run after the board or an open slip is drawn, and again once fonts load) shrinks a name still wider than its line, in cqw, from `slip.itemFont.size` down to `.min`.  Fewer orders show when fewer items qualify, and none shows the note (`orders.emptyText`).  Orders live in memory only (`GW.ship.orders()`): closing the door, or leaving and re-entering the view, clears them.  `.ship-board` is placed by `layouts.<layout>.board` ([x, y, w, h] in % of the room) and sits under the truck and driver; every slip gets the same size, as tall as fits three across.  A slip (`.ship-slip`) is the parchment `<img>` with live text and the region stamp over it, laid out from the approved mock in container query units, so the same markup works small and open.  A trusted tap opens it full size in `.ship-slip-view`, which covers the room so the chain and the rest get no taps; any tap or Escape closes it.  The door and trip start closed each time the view opens and are not saved.  Taps elsewhere in the room do nothing.  The factory rests while the room is showing (see the game loop above).  **Packing (1d).**  Orders are packed left to right; the active order is the first one with no record (`GW.ship.activeOrder()`), and its slip gets `.is-active` (lifted, glowing), packed slips `.is-packed` and a check.  `.ship-conveyor` is an invisible tap area over the painted belt (`layouts.<layout>.conveyor`); a trusted tap opens the item menu, `.ship-menu-items` (placed by `layouts.<layout>.menu`), shelf-style tiles for the groups in `CONFIG.shipping.pack.groups`, built fresh on each open.  Tiles with `orders.keep` or fewer are `.is-off`.  Dragging is done by hand on pointer events with pointer capture on the list: a mouse picks a tile up after `pack.slopPx`; a finger scrolls the list (it is `touch-action: none`, scrolled in code) unless it holds still `pack.holdMs` or leaves the menu, which picks up the tile it pressed.  A `.ship-ghost` on `document.body` follows the pointer, and a drop within `pack.dropPad` of an open box fills it with the active order's `qty` of the dropped item (right or wrong), or what the shelf can spare if fewer (its count less `orders.keep` less what stamped boxes already hold of it).  A capture-phase `pointerdown` on the document closes the menu on any tap outside it, and inside the room that tap does nothing else; Escape closes it too.  The menu's frame is `.ship-menu-frame`, the 05a supply drawer behind the tiles as a nine-slice `border-image` (`pack.menuFrame`: the picture, the slice, and the drawn width per layout); Night dims the frame only.  The box (`.ship-box`, placed by `layouts.<layout>.box`) stacks the open and closed pictures, a label, and the stamp mark (`pack.label`, `pack.mark`).  The label is the item's picture alone and shows only while the box is open and filled.  The mark is drawn solid and straight in the postage corner of the front face (box face v0.3: the same gap from the face's top and right edges, measured on the box art inside its canvas; `pack.mark` holds the result); a stamped box gets `.is-stamped` (z-index 3, inside `#ship`, which is `isolation: isolate`), so it draws above the open box, the stack, and the driver; the menus (4) and an open slip (5) stay above it.  `GW.ship.boxState()`: `open` (empty or filled), `closed` (a tap on a filled open box; a tap opens it again), `stamped`, or `none`.  **The supplies menu (1g).**  `.ship-computer` is an invisible tap area over the painted computer (`layouts.<layout>.computer.hit`); a trusted tap opens `.ship-menu-supplies`, built by the same `buildMenu()` as the item menu (same place, frame, scroll, and drag code; each menu is `{ kind, el, list }` in `menus`, and `GW.ship.menuKind()` says which is open, `items`, `supplies`, or null).  Opening one closes the other; a tap on the open menu's own button closes it, and the capture-phase handler lets taps on either button through so they switch menus.  The supplies menu shows `pack.supplies.sections` in order with headings, skipping empty ones; layer 1 has Packing (1i), Stickers (1j), and Stamps, one tile per region in `pack.stamps`.  Each tile carries a thing with a `side`: junk is `inside` (an open box takes it), a stamp `outside` (a closed box takes it).  A drop over the box (`overBox()`, open or closed) applies it when `fits()`, else runs `shakeBox()` (`pack.shake`): a stamp on an open box, junk or an inside supply on a closed one.  **Inside supplies (1i).**  The supplies menu opens with `makeChart()`, the "Packing rules" chart (`pack.chart`: a title and rows of `{ icon, text }`, the icon an inside supply's id or a tag's id), then the Packing section (`pack.inside`: peanuts and bubble wrap, each `{ id, name, img, spot }`; their tiles carry `side: 'inside'`, `kind: 'supply'`).  A drop on an open box runs `addSupply()`, which sets `boxIn[id]` (a second drop changes nothing); a new item dropped in keeps them.  `makeBox()` adds one `.box-in` picture per inside supply at its `spot` in the opening, shown by `showBox()` only while the box is open and holds it.  The packing tags (`pack.tags`: name and icon per tag) show through `tagIcon()`: `.tile-tag` in a junk tile's top right corner, and `.box-tag` beside the item's picture on the open box's label. Reopening a stickered box hides its stickers and keeps them.  The chart (`.ship-rules`) is hidden under `.no-hints`, bar and all.  **The chart's bar (1k):** the chart's heading is `.ship-rules-head`, a `<button>` with the title and `.ship-rules-chev`, an inline SVG chevron (`chevron()`), with `.ship-rules-rows` under it.  `.is-min` hides the rows and leaves the chevron pointing down; open, the css turns it up over `pack.chart.turnMs`.  A tap on the bar goes through the menu's own pointer handling (`menuUp()` toggles when the press never became a scroll), and keyboard clicks through the button's `click` (`detail` 0).  `makeChart()` reads `localStorage[pack.chart.storeKey]`: none yet shows it open and stores `min` (only while instructions are on), `open` or `min` is the player's last choice, written by `toggleRules()`.  A pressed tile gets `.is-held`.  Stamping animates the mark down, plays `GW.sfx.thump()`, records `{ item, count, inside, outside, stamp }` for that order (`inside` = the inside supplies, in `pack.inside` order; `outside` = the stickers, in `pack.stickers.list` order) (`GW.ship.packed()`, for 1e), then slides the box to its spot in the stack (`layouts.<layout>.stack`) and makes the next order's box.  The box and stack draw in front of the driver.  Nothing is saved and the shelf does not change; closing the door, or leaving the view, clears the record and every box.  **The room holds still on touch screens:** `#ship` is `touch-action: none`, so no pan, pinch, or double-tap zoom starts in it; `html.ship-still` (set while the view is open) turns off overscroll and pull-to-refresh at 720px and under; `main.js` skips the view swipe in the Shipping view; and on entering the view in the tall layout the page scrolls the whole room into view.  **The hand-off (1e).**  When every order has a stamped box, the chain gets `.is-ready` (a glow, and a sway from its top through the CSS `rotate` property, none with reduced motion) and `.ship-finish`, the "Pull to ship!" tag (`finish.text`), shows by its handle (`layouts.<layout>.finishTag`). Since 1j, a box whose packed item has a sticker's `need` tag needs that sticker in its `outside` (FRAGILE for Breakable, HEAVY for Heavy), else that sticker's `reason`.  The card's reason line is `mainWhy()`: the first reason, then `score.more` ("+N") for the rest; the row's screen-reader label lists them all.  A closed but unstamped box still on the bench ships with "No stamp"; an open or empty one is "Not packed" and does not ship.  Each right order adds `score.regions.<region>.right`, each miss subtracts `.wrong`.  `applyShift()` then writes the save at once: every shipped box (wrong items too) takes its packed count off the shelf, never below `orders.keep`; `s.stonks` moves, never below 0; the new total joins `s.stonksHistory` (last `ticker.history`); the shelf is rebuilt and the game saved.  A perfect shift swaps the driver to the happy pose (`driver.happy`, shifted by `shiftX` so his feet stay put) for `driver.happyMs` before he walks out smiling; otherwise he leaves grumpy.  Once the door shows closed, `.ship-card-view` covers the room with the report card (`card`: the paper with live rows in container units: the tick, the town, the item, the reason, the item's picture, and "Stonks this shift").  The town, item, and reason are `.card-line`s, one line each: `fitCard()` runs when the card shows (and again once fonts load) and shrinks any line wider than its row, in cqw, from `card.font` down to `card.fontMin`, past which the css ends it with "...".  `GW.ship.testCard(r)` shows a card for made-up rows without scoring or saving, for screenshots. A trip with no orders scores nothing and shows no card.  **The room's tips (1g).**  `.ship-belt-glow` and `.ship-screen-glow` repeat the room art cut to `layouts.<layout>.belt` and `.computer.screen`, brightened under a gold `drop-shadow` that breathes over `tips.pulseMs` (steady with reduced motion); they sit just above the room, under everything else.  `updateReady()` shows the belt's glow and `.ship-belt-tag` (`tips.belt`, placed by `layouts.<layout>.beltTag`) from the trip's first box until the item menu first opens (`beltTip`, reset by `newOrders()`), and the screen's glow while the box on the bench is `closed`.  Every tip carries `.ship-tip`, and `.no-hints` (the instructions setting, `gnomeworks.hints`) hides them all and calms the ready chain to its plain look.  While the Packing Line shows, `main.js` sets the setting's label to `tips.setting`.  **Leaving mid-trip (1f).**  `main.js` asks `GW.ship.holdLeave(go)` before switching from the Shipping view; it returns true to hold the switch.  While the trip is `here` with orders, it opens `.ship-warn-view` (z-index 6, over the card), the leave warning (`CONFIG.shipping.leave`: the words, its width per layout, and the slip paper drawn as a nine-slice `border-image`; the panel is a size container and its inner `.warn-body` uses cqw).  Stay, a tap outside the panel (a capture-phase `pointerdown` on the document), or Escape closes it.  Send it off calls `pull()`, so scoring and the trip are the chain's own, and keeps `go` in `afterCard`.  While the trip is `leaving`, `holdLeave` keeps `go` in `afterCard` with no warning.  `closeCard()` runs `afterCard` after the tick-up, so the view switches once the card closes.  Tapping Shipping again (`GW.ship.stay()`) drops a waiting leave.  `holdLeave(go, heard)` calls `heard` whenever a leave is set to wait for the card (after the pull, or Send it off), and `main.js` uses it to give the tapped view button `.is-waiting` (pressed and lit) until `applyView()` clears it on the switch (1k).  With the door closed, or a trip with no orders, `holdLeave` returns false and the view switches at once.  `.ship-stonks` sits inside the painted STONKS glass (`layouts.<layout>.stonks`): `ticker.label`, the number, and an SVG polyline of `stonksHistory`, spread across the full width first to last (one shift is a flat line across at its value), with a dot at the newest; it is drawn from the save on entering the view and animated (`ticker.tickMs`) only when the card closes.

**Squish and boing.**  Each station part is a wrapper holding the static image, the action image stacked on top (hidden), and optional extras (hat, weapon, slash).  On each beat the wrapper squashes, swaps to the action frame mid-squash (`.act` class), stretches, and settles.  Beat speed follows that gnome type's real click rate, between 2.2 and 0.45 seconds.  The warrior's weapon and the hat move between static and action positions through CSS variables.  Animations stop when paused or off the floor view.  Devices that ask for reduced motion get slower pose swaps with no squash, stretch, or shake.

## Shelf (`ui.js`)

Built once per container (the desktop side column and the phone Shelf tab), then updated in place so open groups stay open.  Groups fold open with a found/total count and a NEW pill.  Groups with `layout: 'families'` (Tiny Monsters, Number Twos) draw one row per family with a fixed column per variant, leaving gaps for missing variants.

## Sound (`sfx.js`)

Almost every sound is built from oscillators and filtered noise at play time.  Recorded samples (the clone giggle and the splash) load from `assets/sfx/` when served over http and fall back to code-made versions if they can't load or the page is opened from disk.  A compressor on the master output keeps peaks safe.  Sound unlocks on the first trusted tap (browser rule).  `navigator.audioSession.type = 'ambient'` lets game sounds mix with a player's own music on iPhones.  Rate limits: taps 12 a second, drops 4 a second, gnome chatter about 2 a second shared.  Settings (effects volume, chatter on/off, mute) live in the save.

## Responsive layout (`style.css`)

- Over 1100px: three columns (shelf, machine, shop panel), up to 1800px wide.  Both side panels are clipboards (`border-image` slices 281 / 70 / 218 on an 844 x 1080 picture; `--cb` scales them, set in `main.js`).  When the space beside the machine is at least `layout.railMinWidth` (100px), the next-item gauge and the crew move into side rails next to it.
- 721 to 1100px: two columns; the shelf moves into a Shelf tab.
- 720px and under: one column; the tall Shop Floor layout.  Everything sits on the one clipboard.
- Night theme: CSS under `.night`, plus picture swaps through `GW.theme.img()`.
- The machine box is square in Machine view and takes the floor background's aspect in Shop Floor view.
